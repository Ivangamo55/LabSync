2. Construcción y ejecución

2.1 Prerrequisitos

  • JDK completo 17 o superior: java y javac deben existir.
  • Conectividad a Maven Central en la primera compilación.
  • MySQL/MariaDB solo para pruebas de integración o ejecución funcional.
  • Servidor gráfico para abrir Swing. En CI sin pantalla, no arrancar el JAR.
java -version
javac -version
./mvnw -version
Diagnóstico importante: algunas distribuciones instalan un paquete Java headless que incluye java y el módulo del compilador, pero omite javac, ct.sym o libawt_xawt. En ese caso Maven puede informar “release version 17 not supported” y Swing “HeadlessException”. Instale el paquete JDK/devel completo y el soporte gráfico.

2.2 Construcción reproducible

Desde la raíz, nunca presuponga Maven global:

# Linux/macOS
./mvnw clean verify

# Windows PowerShell/CMD
.\mvnw.cmd clean verify

El POM padre llama al módulo. La fase verify compila con maven.compiler.release=17, ejecuta Surefire/JUnit, crea el JAR, lo sombrea con dependencias y genera JaCoCo.

SalidaRutaVerificación
JAR ejecutableLabSync/target/LabSync-1.0.jarManifest contiene Main-Class: labsync.aplicacion.AplicacionLabSync.
Resultados JUnitLabSync/target/surefire-reports/XML/TXT por clase.
CoberturaLabSync/target/site/jacoco/index.htmlAbrir en navegador después de verify.

2.3 Ejecución

# Linux/macOS
java -jar ./LabSync/target/LabSync-1.0.jar

# Windows
java -jar .\LabSync\target\LabSync-1.0.jar

También puede usarse Ejecutar-LabSync.cmd. AplicacionLabSync.main delega en SwingUtilities.invokeLater, construye VentanaInicioSesion, la centra y muestra en el Event Dispatch Thread.

3.1 Precedencia de configuración JDBC

No use los predeterminados en producción. Cree un usuario de aplicación con privilegios mínimos; mantenga secretos fuera del repositorio y del historial de comandos.

3.2 Instalación nueva

  1. Respalde cualquier esquema homónimo.
  2. Inicie MySQL/MariaDB en el host configurado.
  3. Importe una sola vez labsync_db/labsync_db.sql. El archivo crea/selecciona labsync_db y define el esquema completo.
  4. Cree datos maestros y cuentas de prueba; el DDL no incluye datos iniciales.
  5. Valide exactamente 14 tablas.
mysql -u root -p < labsync_db/labsync_db.sql
mysql -u root -p -D labsync_db -e "SHOW TABLES;"

Para un nombre de esquema distinto, prepare una copia revisada del DDL y ajuste tanto CREATE DATABASE/USE como la URL JDBC. No haga reemplazos a ciegas en producción.

3.3 Migraciones

Procedimiento: respaldo consistente → ensayo en copia → importar labsync_db/labsync_db.sql → revisar conteos, restricciones y triggers → ejecutar pruebas de humo → documentar versión. El archivo recrea las tablas, por lo que no debe importarse sobre datos que no estén respaldados.

4.2 Reglas de mantenimiento del GUI

  • Los archivos .form pertenecen al diseñador NetBeans. No edite manualmente bloques initComponents marcados como generados.
  • Las consultas lentas no deben ejecutarse en el Event Dispatch Thread. ActualizacionAutomatica usa trabajo en segundo plano y aplica el resultado en Swing.
  • Toda mutación visual debe volver al EDT.
  • Los recursos se cargan desde classpath mediante Recursos; no dependa del directorio actual.
  • La navegación preserva SesionUsuario y dispone la ventana anterior.

5. Flujos y reglas transaccionales

5.1 Autenticación

correo + contraseña→SHA-256 hexadecimal→SELECT usuario→SesionUsuario→panel por rol

SesionUsuario lleva identificador, nombre corto, nombre completo y rol. El ID es esencial para asociar reservas, bitácora y resoluciones al usuario real; no sustituirlo por texto visible.

5.2 Registro

  1. Validación de campos, rol y dominio institucional.
  2. Captura adicional por rol.
  3. setAutoCommit(false).
  4. INSERT en usuario y lectura de clave generada.
  5. INSERT opcional en estudiante, laboratorista o externo.
  6. commit; ante cualquier excepción, rollback.

5.3 Disponibilidad y aprobación

consultar(laboratorio, fecha, intervalo, rol) ├─ ¿laboratorio Disponible y capacidad > 0? ├─ ¿mantenimiento Pendiente/En proceso cuya fecha ya aplica? ├─ ¿reporte de falla En revisión? ├─ ¿clase regular activa en ciclo/día con traslape? ├─ ¿reserva activa de profesor? ├─ profesor: ¿hay reservas individuales activas? └─ estudiante: capacidad = total_equipos − alumnos activos └─ disponible si capacidad restante > 0

Los estados activos para ocupación son Pendiente y Aprobada. El traslape usa la condición de intervalos inicioA < finB AND finA > inicioB. La aprobación reconsulta dentro de transacción y puede añadir FOR UPDATE para reducir carreras entre sesiones.

5.4 Horarios regulares

ServicioHorarios valida carrera, cuatrimestre 1–11, grupo, turno, materia, módulos de hora y rango del turno. Busca conflictos por laboratorio, profesor o identidad del grupo dentro del ciclo/día. Los triggers repiten integridad crítica en la base.

TurnoVentanaInicios/finales
Matutino07:00–14:10Módulos institucionales de 50 min, con los bloques definidos en el servicio.
Vespertino15:00–21:20Módulos institucionales de 50 min.

5.5 Mantenimiento e inventario

ServicioMantenimiento valida el equipo, tipo, fecha, responsable, estado y observaciones especiales; impide conflictos con reservas cuando corresponda; inserta/actualiza en transacción y sincroniza el estado de inventario.

TransiciónEfecto de inventario
Pendiente o En procesoEquipo En mantenimiento.
Realizado: preventivo/correctivo/actualizaciónDisponible y ultimo_mantenimiento actualizado.
Realizado: disposición peligrosa/retiro obsoletoBaja, sin borrar historial; observaciones obligatorias.
CanceladoFinaliza la programación; el servicio recalcula el estado aplicable.

5.6 Alertas

ServicioAlertas sincroniza avisos idempotentes respaldados por la clave única tipo + referencia y un único origen relacional. Genera alertas para mantenimiento próximo/vencido, preventivo requerido, fallas, equipos con fallas, reservas pendientes y resoluciones.

Los controles de campana y el diálogo actualizan aproximadamente cada 7 segundos. La operación que cambia una alerta debe conservar el origen y actualizar fechas de lectura/atención.

6.2 Reglas de integridad a preservar

  • Correos, nombres de laboratorio, matrícula, código/serie y nombres de ciclo no se repiten según sus claves únicas.
  • Capacidades y totales de usuarios son positivos.
  • Fecha final del ciclo no precede al inicio; hora final es posterior a inicio.
  • El profesor de horarios_clase debe tener rol Profesor.
  • La fotografía de laboratorio en bitácora/falla debe coincidir con su FK cuando aplica.
  • Una alerta tiene exactamente una FK de origen no nula.
  • No elimine físicamente equipos/software que requieran historial: use Baja/Eliminado.

7. Interfaz, sesión y concurrencia

7.1 Ciclo de vida de ventana

Los constructores reciben preferentemente SesionUsuario. Existen sobrecargas con nombre por compatibilidad, pero el camino nuevo debe conservar el objeto de sesión. Al navegar se crea la siguiente ventana, se centra/muestra y se dispone la anterior. Los temporizadores se detienen al cerrar para evitar fugas.

7.2 Actualización automática

ActualizacionAutomatica<T> recibe ventana, intervalo, proveedor de datos y consumidor visual. Un Timer inicia lecturas y el resultado se aplica sin bloquear Swing. Varias pantallas usan 7000 ms: dashboards, reservas, fallas, inventario/software, mantenimiento, horarios, bitácora y alertas.

  • No cambie el modelo de una tabla si la selección/edición activa se perderá sin restauración.
  • Use ActualizadorModeloTabla para conservar selección y evitar parpadeo cuando el contenido no cambió.
  • Los fallos de refresco deben registrarse y presentar un estado controlado, no cerrar la ventana.

7.3 Exportación

Las ventanas administrativas crean libros XLSX con Apache POI, título, encabezados, filas visibles, formato y autofiltro. Los nombres predeterminados son específicos del módulo. Cierre streams/workbooks con try-with-resources y no ejecute escritura pesada en EDT si el volumen crece.

8.2 Cobertura

El reporte global de la ejecución documentada cubrió 579 de 11,377 líneas (~5.1%) y 282 de 2,177 ramas (~13.0%). 9.3 SQL de comprobación

-- Tablas y versión funcional
SELECT COUNT(*) AS tablas
FROM information_schema.tables
WHERE table_schema = DATABASE();

-- Reservas por estado
SELECT estado, COUNT(*) FROM reservas GROUP BY estado;

-- Doble ocupación potencial (inspección orientativa)
SELECT a.id_reserva, b.id_reserva, a.id_laboratorio, a.fecha
FROM reservas a JOIN reservas b
  ON a.id_reserva < b.id_reserva
 AND a.id_laboratorio = b.id_laboratorio
 AND a.fecha = b.fecha
 AND a.hora_inicio < b.hora_fin
 AND a.hora_fin > b.hora_inicio
WHERE a.estado IN ('Pendiente','Aprobada')
  AND b.estado IN ('Pendiente','Aprobada');

-- Alertas con origen inválido: debe devolver 0
SELECT COUNT(*) AS invalidas FROM alertas
WHERE ((id_reserva IS NOT NULL) + (id_falla IS NOT NULL) +
       (id_mantenimiento IS NOT NULL) + (id_inventario IS NOT NULL)) <> 1;

La consulta de traslapes es orientativa: reservas individuales compatibles pueden coexistir hasta capacidad. Cruce con rol/cantidad antes de reportar defecto.

9.4 Concurrencia crítica

  1. Abra dos sesiones de laboratorista sobre la misma base.
  2. Seleccione la misma reserva Pendiente.
  3. Intente aprobar en ambas casi simultáneamente.
  4. Verifique un solo resultado coherente, sin pérdida de actualización ni doble ocupación.
  5. Repita con dos reservas incompatibles consultadas como libres antes de aprobar.

11. Operación, respaldo y migraciones

11.1 Respaldo

mysqldump --single-transaction --routines --triggers \
  -u operador -p labsync_db > /ruta/fuera-del-repositorio/respaldo.dump

Compruebe tamaño, restaure periódicamente en un servidor aislado y proteja el archivo porque contiene correos, nombres y hashes. Defina retención y cifrado según política institucional.

11.2 Monitoreo mínimo

  • Disponibilidad y latencia del servidor SQL.
  • Crecimiento de bitácora, alertas, fallas y reservas.
  • Errores SQL del proceso Java y deadlocks.
  • Espacio para respaldos y exportaciones.
  • Desfase de reloj entre estaciones y servidor.

11.3 Reversión

El repositorio no ofrece una migración automática de reversa 14→13. Antes de migrar, conserve respaldo y binario anterior. Si la liberación falla, detenga escrituras, restaure el respaldo en un esquema nuevo, apunte el binario anterior a ese esquema y valide. No elimine únicamente software_laboratorio si la aplicación nueva sigue activa.

12. Seguridad y deuda técnica

HallazgoRiesgoRecomendación
Contraseñas con SHA-256 sin salResistencia insuficiente ante robo de hashes.Migrar gradualmente a Argon2id o bcrypt con sal individual y rehash al iniciar sesión.
Credenciales predeterminadas root/vacíaPrivilegios excesivos y configuración insegura.Usuario dedicado, privilegios mínimos y secreto externo.
JDBC directo sin poolConexiones repetidas y observabilidad limitada.Evaluar datasource/pool y timeouts antes de escalar.
Lógica SQL aún presente en ventanasDifícil prueba y acoplamiento UI/datos.Mover gradualmente a servicios/repositorios transaccionales.
Cobertura GUI bajaRegresiones visuales o de navegación.Pruebas de componentes/robot en entorno gráfico controlado y casos manuales versionados.
Rol Externo sin interfazCuenta válida sin flujo útil.Ocultar alta, bloquear acceso o implementar el panel según producto.

Las consultas observadas usan PreparedStatement, reduciendo inyección SQL. Mantenga esa práctica, valide identificadores dinámicos y nunca concatene entrada del usuario en SQL.

Table '...software_laboratorio' doesn't existInstalación incompleta u obsoleta.Respaldar e importar labsync_db/labsync_db.sql.
Error de clave duplicadaCorreo, matrícula, código, serie, ciclo o software/lab repetido.Consultar la fila existente; no eludir la restricción.
Reserva rechazada al aprobarCambio concurrente, clase, mantenimiento, falla o capacidad.Es comportamiento esperado si la revalidación explica el bloqueo.
GUI congeladaI/O en EDT, diálogo modal oculto o servidor lento.Tomar thread dump; buscar AWT-EventQueue y mover consulta a worker.
Modelo de tabla cambia selecciónRefresco periódico reemplaza filas.Usar utilidades de actualización/selección estable.
XLSX no se escribePermisos, archivo abierto o sin filas.Probar ruta escribible, cerrar archivo y revisar excepción POI.
